A student's scores on the wrong row is the worst class of bug this tool has had. Be exact.

1. IMP-01 (Critical). Two students with the same IXL name in one course export. The roster fixer saves the COURSE key ("JORDAN LEE#1"), but a class numbers its own students in roster order, so the saved pick either never resolves (the student stays "not found in IXL", probe 01) or, when both are in ONE class, points at the other student: their scores swap with status ok (c01-twins-same-class-swap.js: the one picked for 95s reads 60). Fix (tried by the counter, see tried-fixes-app.js.patch): materialize stores on the class the course keys of the students it carved (`sec.poolKeys`); ixlList uses them when the class is a pool class without its own export (`pool && !fromSection`) and the lengths match; poolRows' view sets `poolKeys: null`. tests/pool.js has one check that passed only thanks to this bug (its "#1" pick never resolved, so the fixer reopened): see tried-fixes-pool-test.patch. Probes 01 and c01 must both pass.
2. CTR-01 (Critical if real: it was found by the counter agent and nobody has challenged it yet, so reproduce it yourself first with c06-moved-student-best.js and make sure a real weekly drop reaches that state). A student who moves between two classes of one course loses his kept best scores, because the best is kept per class: best 80 becomes 50, the unit's points go from 4 to 0, and that is what Copy would paste into Focus. README: "Best score across imports is kept." Fix: when a class is carved from the course export, a student it takes who was in another class of that course brings his kept best scores with him, matched by the course key (never by name alone: two students of one name must not share bests). If the trigger turns out not to be real, skip it and say exactly why.
3. IMP-06 (Medium). The weekly "drop all the files in any order" depends on the order when a student changed classes and Focus spells the name differently from IXL: a class's carve reads the other classes' rosters, and each gradebook re-carves only its own class. Fix (tried): after the gradebook loop, re-carve every pool class of each course touched, once. Do not add these classes to the import card's `ok` list (it would add a false "IXL export" line for classes that keep their own newer export). Probe 06.
4. IXL-02 (Medium, from the IXL audit). After an import that swaps one student for another with the class size unchanged, the history snapshot uses the previous export's student keys: the object literal near line 568 spreads `prev` and carries the old `_keys` cache, and snapshot() runs before the cache is cleared. Fix: `_keys: null` in that literal, and ixlKeyAt checks its cache by identity (the students array it was built from), not by length. Probe: review/audit-nov15/probes/ixl/02-*.
5. IMP-03 (Medium). A file whose name says "Last-School-Year" replaces this year's course data without a word (the kept best scores hold the points, but the class shows the old file as current, raw scores go blank and history gets a false week). Fix: ask once, like the existing question for an older export, saying what the file is and what taking it would do. Probe 03 and c03-last-year-damage.js.
